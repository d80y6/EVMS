# EVMS Beta Release Implementation Plan

> **For agentic workers:** Execute tickets sequentially. Each ticket must be independently testable. Verify runtime behavior after each ticket.

**Goal:** Elevate EVMS from prototype to Beta candidate — deployable, stable, secure enough for pilot customers, operational, observable, recoverable, testable.

**Architecture:** Microservice Go backend with NATS messaging, TimescaleDB, WebRTC streaming, AI inference pipeline. Helm-deployed on Kubernetes. Docker Compose for dev.

**Tech Stack:** Go 1.24, NATS, TimescaleDB, WebRTC, FFmpeg, ONVIF, OTel, Prometheus, Grafana, Loki

### C2: Add FFmpeg Input Validation

**Purpose:** FFmpeg is invoked with args that may contain user-controlled or camera-controlled input (RTSP URLs, file paths). Validate inputs to prevent argument injection.

**Affected services:** ingest, recorder, thumbnails, ai-worker, export

**Files to modify:**
- `services/ingest/main.go` — validate RTSP_URL, CameraID before passing to FFmpeg
- `services/recorder/main.go` — validate cameraID in FFmpeg args
- `services/thumbnails/main.go` — validate recordingPath before FFmpeg
- `services/ai-worker/blur.go` — validate input paths
- `services/ai-worker/lpr.go` — validate input paths
- `services/export/main.go` — validate segment paths
- `pkg/common/validate.go` — (create) common validation helpers

**Implementation tasks:**
1. Create `pkg/common/validate.go` with:
   - `ValidateRTSPURL(url string) error` — must be rtsp://, no shell chars
   - `SanitizeCameraID(id string) string` — alphanumeric + hyphens only
   - `ValidateFilePath(path string, allowedRoot string) error` — must be under allowed root, no `..`
2. Ingest: validate `RTSPURL` and `CameraID` before constructing FFmpeg args
3. Recorder: validate `cameraID` in FFmpeg calls
4. Thumbnails: validate `recordingPath` before FFmpeg call
5. AI worker: validate input paths to openalpr and FFmpeg
6. Export: validate segment paths

**Test requirements:**
- `validate_test.go` tests for all validation functions
- Inject malicious RTSP URL → rejected
- Inject path with `..` → rejected
- Valid RTSP URL → accepted

**Acceptance criteria:**
- All FFmpeg invocations validate inputs for injection characters
- RTSP URLs checked for valid scheme and no shell metacharacters
- File paths checked for path traversal

**Runtime validation:**
```bash
go test ./pkg/common/... -run TestValidate -v
```

   - Block loopback addresses (127.0.0.1, ::1, 0.0.0.0)
   - Block link-local addresses (169.254.x.x)
   - Block private ranges beyond current check (10.x.x.x, 172.16-31.x.x, 192.168.x.x)
   - Add DNS rebinding protection (resolve target, cache, verify)
2. In notification `main.go`, add same URL validation before POST
3. Add timeout enforcement for all webhook calls (10s max)

**Test requirements:**
- Test SSRF blocker rejects private IPs
- Test SSRF blocker rejects loopback
- Test SSRF blocker accepts public HTTPS URLs
- Test webhook timeout enforcement

**Acceptance criteria:**
- No service can be tricked into making requests to internal infrastructure
- Webhook calls have 10s max timeout
- DNS rebinding attack mitigated via resolution + validation
